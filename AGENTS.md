# AGENTS.md — Visit Polzela Codebase Guide

## Architecture Overview

This is a **Quarkus 3 + Vaadin Flow 24** app whose UI is a pure **React 18 + TypeScript** SPA. Vaadin is used exclusively as a build/packaging harness — there are **no Vaadin Flow server-side UI components** in use. The React app is bundled by Vite (via Vaadin's Maven plugin) and served as static resources by Quarkus.

```
Browser → Quarkus (serves static files) → React SPA (React Router)
                  ↓
         META-INF/resources/ (POI text files, images, etc.)
```

- **Two routes only**: `/` (`MainView.tsx`) and `/poi/:name` (`POIDetailView.tsx`)
- **No backend API**: All data comes from flat text files fetched at runtime and cached in IndexedDB
- **Offline-first**: Service worker + IndexedDB ensure the app works without a network connection

## Developer Workflows

**Dev mode (hot reload on both Java and frontend):**
```bash
mvnw quarkus:dev          # Windows
./mvnw quarkus:dev        # Mac/Linux
# App available at https://localhost:8080 — accept the self-signed cert
```

**Production build (outputs `target/visit-polzela-1.0-runner.jar`):**
```bash
mvnw package -Pproduction -DskipTests
java -jar target/visit-polzela-1.0-runner.jar
```

**Docker:**
```bash
docker build -t visit-polzela .
docker run -p 8080:8080 visit-polzela
```

**Reset cached data (when POI data changes during dev):**  
Open DevTools → Application → Storage → clear IndexedDB `visit-polzela` and reload. Or increment `DATA_VERSION` in `DataService.ts`.

## Data Architecture

All content lives in `src/main/resources/META-INF/resources/`:

| File | Format | Purpose |
|------|--------|---------|
| `pointsofinterest/pois.txt` | `;`-delimited, one POI per line | POI records: `key;displayName;shortDesc;osmUrl;googleMapsUrl;appleMapsUrl` |
| `pointsofinterest/poititles.txt` | `;`-delimited | Localized titles + UI strings: `key;EN:…;SL:…;DE:…;NL:…` |
| `poi-descriptions/[key].txt` | Line-prefixed | Long descriptions: `EN:…`, `SL:…`, `DE:…`, `NL:…` (one lang per line) |
| `images/[key].webp` | WebP | Main POI image; gallery: `[key]1.webp`, `[key]2.webp`, `[key]3.webp` |

**Data flow**: text files → `DataService.ts` (fetch + parse) → IndexedDB (`idb`) → React state.

The singleton `DataService` (`services/DataService.ts`) is the only data access layer. Call `DataService.getInstance()` everywhere.

**Cache busting**: increment `DATA_VERSION` constant in `DataService.ts` to force re-fetch on next app load.

## Internationalization Pattern

Supported languages: `EN | SL | DE | NL` (type `Language` in `types/POI.ts`).

- **UI strings & POI titles**: `poititles.txt` — key/lang format, retrieved via `dataService.getLocalizedText('key', language)`
- **Long descriptions**: `poi-descriptions/[key].txt` — fetched directly in `POIDetailView.tsx`
- **Language persistence**: `localStorage.setItem('selectedLanguage', lang)` — read on component mount

To add a new UI string: append a line to `poititles.txt` and call `dataService.getLocalizedText('newkey', language)`.

## Adding a New POI

1. Append a line to `pois.txt`: `poikey;Display Name;Short desc;osmUrl;googleMapsUrl;appleMapsUrl`
2. Append a line to `poititles.txt`: `poikey;EN:…;SL:…;DE:…;NL:…`
3. Create `poi-descriptions/poikey.txt` with `EN:`, `SL:`, `DE:`, `NL:` prefixed lines
4. Add `images/poikey.webp` (main) and optionally `poikey1-3.webp` (gallery)
5. Increment `DATA_VERSION` in `DataService.ts`

POI display order is determined by line order in `pois.txt`.

## Key Conventions

- **Leaflet is loaded globally** (not bundled). `POIDetailView.tsx` accesses it as `(window as any).L` — do not import Leaflet directly.
- **`vite.config.ts` only contains overrides** — the real Vite config is in `vite.generated.ts` (auto-generated by Vaadin, do not manually edit it).
- **`vaadin.pwa.enabled=false`** in `application.properties` — the custom `sw.js` in `META-INF/resources/` is used instead of Vaadin's built-in PWA support.
- **SEO**: use the `<SEO>` component (`components/SEO.tsx`) with `react-helmet-async` and structured data helpers from `utils/seoHelpers.ts`.
- **Styles**: per-view CSS files in `styles/`; max content width is 800px; responsive breakpoints at 768px and 480px.
- **No tests** currently exist in the project.

## Key Files

| Path | Role |
|------|------|
| `src/main/frontend/services/DataService.ts` | All data loading, IndexedDB, i18n lookup |
| `src/main/frontend/types/POI.ts` | `POI`, `POITitle`, `Language` types |
| `src/main/frontend/views/MainView.tsx` | Home page — POI grid + language switcher |

| `src/main/resources/application.properties` | Quarkus config (`PORT` env var, uber-jar, static paths) |
